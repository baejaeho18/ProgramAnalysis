## 강의 12 — Application 1 (Locks)

### 문제 12-1 [개념·서술] (M, 슬라이드 6~10)
C 락의 두 가지 **암묵적 관계**(데이터-락, 흐름-락)를 정의하고, Rust의 `Mutex`/`MutexGuard`가 각각을 어떻게 **명시적**으로 만드는지 설명하라.

**풀이.**
- **데이터-락 관계**: "어떤 락이 어떤 데이터를 보호하는가." C에선 락과 데이터가 따로 선언되어 짝이 코드에 없다. Rust는 `Mutex<T>`가 **락과 데이터를 한 컨테이너로 묶어**(Rust 락 = C 락 + 데이터) 짝을 타입에 고정 → 엉뚱한 락 잡기 불가.
- **흐름-락 관계**: "프로그램의 각 지점에서 어떤 락이 잡혀 있는가." C에선 lock/unlock 사이를 사람이 추적해야 한다. Rust는 **가드의 수명(lifetime)**이 곧 보호 구간 — 가드가 살아 있으면 락 보유, `drop`되면 해제. RAII로 컴파일러가 정적으로 추적 → 보호 구간 밖 접근은 컴파일 에러.

### 문제 12-2 [계산·추적] (M, 슬라이드 15~18) ★
다음 함수에 **live guard 분석**(후방·may)과 **available guard 분석**(전방·must)을 각각 손으로 돌려 각 지점의 락 집합을 구하고, 함수 요약 `(진입, 반환)`을 답하라.
```c
void foo() {
  pthread_mutex_lock(&m);
  n = n + 1;
  pthread_mutex_unlock(&m);
  pthread_mutex_lock(&k);
}
```

**풀이.**
**Live (후방, 끝에서 시작 `{}`):**
- `lock(&k)` 위: `{}\{k} = {}`
- `unlock(&m)` 위: `{}∪{m} = {m}`
- `n=n+1` 위: `{m}`
- `lock(&m)` 위(=진입): `{m}\{m} = {}`
→ **진입 `{}`**.
**Available (전방, 진입값 = live 결과 `{}`):**
- `lock(&m)` 후: `{}∪{m} = {m}`
- `n=n+1` 후: `{m}`
- `unlock(&m)` 후: `{m}\{m} = {}`
- `lock(&k)` 후(=반환): `{}∪{k} = {k}`
→ **반환 `{k}`**.
**함수 요약: 진입 `{}`, 반환 `{k}`.** (자기 락 m은 잡고 풀어 균형, k는 잡은 채 끝나 반환해야 하는 가드.)

### 문제 12-3 [증명·유도] (S, 슬라이드 15·17)
live guard 분석이 **may**(격자 ⊆, join=∪)이고 available guard 분석이 **must**(격자 ⊇, join=∩)인 이유를, 분기 합류에서 어떤 정보를 보존해야 안전한지로 설명하라.

**풀이.**
- **live = may**: "진입 시 *잡혀 있을 수 있는* 락"을 구한다. 한 경로에서라도 어떤 락이 진입 시 필요하면(잡혀 있어야 하면), 그 가드를 인자로 받아야 안전 → **합집합**으로 모아야 누락이 없다(빠뜨리면 보호 없는 접근 발생).
- **available = must**: "반환 시 *반드시* 잡혀 있는 락"을 구한다. 가드를 반환한다고 단정하려면 **모든** 경로에서 잡혀 있어야 한다. 한 경로라도 안 잡혀 있으면 "반드시"가 깨지므로 → **교집합**으로 공통으로 잡힌 것만 남겨야 안전.
방향: 잡힘을 누락하면 위험한 쪽(live)은 합집합, 잡힘을 과장하면 위험한 쪽(available)은 교집합.

### 문제 12-4 [계산·추적] (M, 슬라이드 24~27) ★
재귀 함수의 고정점 반복을 수행하라. 바닥 요약 `(진입:{}, 반환:LockVar)`에서 시작.
```c
void foo(int n) {
  if (n <= 0) {
    pthread_mutex_unlock(&m);
  } else {
    foo(n - 1);
  }
}
```
1차 반복 후 요약과 2차에서 고정점 여부를 보여라.

**풀이.**
**1차 (요약 진입{}, 반환 LockVar 사용):**
- Live: then 가지 `unlock(&m)` 위 `{m}`; else 가지 `foo(n-1)` 호출은 요약(진입{}, 반환 LockVar) 적용 — live 호출 규칙 `(JOIN \ 반환락) ∪ 진입락` = `({}\LockVar)∪{} = {}`. 진입 합류 `{m}∪{} = {m}`.
- Available: 진입 `{m}`. then: `unlock` 후 `{}`. else: 호출 `(JOIN\진입락)∪반환락 = ({m}\{})∪LockVar = LockVar`. 합류 교집합 `{}∩LockVar = {}`. 반환 `{}`.
- **갱신 요약: 진입 {m}, 반환 {}.**
**2차 (요약 진입{m}, 반환{} 사용):** else 호출이 이제 `({m}\{m})∪{} = {}`(live), available `({m}\{m})∪{} = {}` 후 합류 `{}∩{} = {}`. 결과 요약 또 (진입{m}, 반환{}) → **변화 없음 = 고정점**.
직관(슬25 "결국 락을 푼다")과 일치: 진입에 m 잡혀 들어와 풀고 끝남.

### 문제 12-5 [설계·응용] (F, 슬라이드 32~36)
상향식(bottom-up) 분석만으로는 `inc()`(락을 안 건드리는 함수)가 "진입{} 반환{}"으로 요약된다. 그런데 변환 시 `inc`가 가드를 인자로 받아야 할 수도 있다. **왜 하향식(top-down) 패스가 추가로 필요한지**, 그리고 그 패스가 어떤 조건에서 어떤 정보를 callee로 내려보내는지 설계하라.

**풀이.**
상향식 요약은 함수 *내부*만 본다. 하지만 변환은 "이 함수가 *실제 호출될 때* 호출자 쪽에서 어떤 락이 잡혀 있나"를 알아야 시그니처(가드 인자 여부)를 정한다. 예: `inc`가 항상 m이 잡힌 채 호출되면, `inc` 본문의 `n` 접근도 m 가드를 거쳐야 하므로 `inc(g: MutexGuard) -> MutexGuard`가 되어야 한다.
**하향식 패스**: 상향식이 끝난 뒤 한 번, 각 함수의 **모든 호출 지점에서 공통으로(교집합) 잡힌 락**을 그 함수 내부로 내려보낸다. 교집합인 이유는 must — 한 호출 지점에서라도 안 잡혀 있으면 그 가드를 인자로 받는다고 단정할 수 없기 때문. 상향식으로 요약을 다 구해 두었으므로 하향식은 한 패스면 충분하다.

### 문제 12-6 [계산·추적] (M, 슬라이드 19~20) ★ 〔신규〕
다음 함수는 조건이 참일 때만 m을 잠깐 풀었다가 다시 잡는다.
```c
void foo() {
  if (...) {
    pthread_mutex_unlock(&m);
    ...
    pthread_mutex_lock(&m);
  } else {
    ...
  }
}
```
(a) live guard 분석과 available guard 분석을 각각 손으로 돌려 모든 지점의 락 집합을 구하고 함수 요약을 답하라.
(b) 만약 then 가지 끝의 `pthread_mutex_lock(&m)`이 없다면 반환 집합이 어떻게 되는지, 그것이 must·교집합의 어떤 성질을 보여 주는지 답하라.
(c) (a)의 요약대로 변환된 Rust 함수의 시그니처를 쓰라.

**풀이.**
**(a) Live (후방, 끝 `{}`):** then 가지 — `lock(&m)` 위 `{}\{m}={}`, `...` 위 `{}`, `unlock(&m)` 위 `{}∪{m}={m}`. else 가지 — 내내 `{}`. 분기 직후(진입 직후) 합류는 후방 분석이므로 두 가지의 **시작점이 진입으로 모임**: then 요구 `{m}`, else 요구 `{}` → may·합집합 `{m}∪{}={m}` → **진입 `{m}`** (then 가지의 첫 unlock 때문에 진입 시 m이 잡혀 있어야 함).
**Available (전방, 진입값 = live 결과 `{m}`):** then — `unlock` 후 `{m}\{m}={}`, `...` 후 `{}`, `lock` 후 `{}∪{m}={m}`. else — 내내 `{m}`. 합류(must·교집합) `{m}∩{m}={m}` → **반환 `{m}`**.
**요약: 진입 `{m}`, 반환 `{m}`** — "잠깐 풀었다 다시 잡는" 동작은 함수 안에서만 일어나고 경계(진입·반환)에는 영향이 없다.
**(b)** then 가지가 unlock만 하고 끝나면 then 끝은 `{}`, else 끝은 `{m}` → 반환 `{}∩{m} = ∅`. "모든 경로에서 반드시 잡혀 있음"이 깨지므로 가드를 반환할 수 없다 — 한 경로라도 빠지면 전체를 부정하는 **must(교집합)의 보수성**을 보여 준다(슬20 해설).
**(c)** 진입·반환 모두 `{m}`이므로 가드를 받고 돌려주는 시그니처: `fn foo(g: MutexGuard<...>) -> MutexGuard<...>`. (then 가지의 unlock은 `drop(g)`, 재획득은 `g = m.lock().unwrap()`으로 변환.)

### 문제 12-7 [계산·추적] (M, 슬라이드 28~31) 〔신규〕
다음 재귀 함수에 바닥 요약에서 출발하는 고정점 반복을 수행하라.
```c
void foo(int n) {
  if (n <= 0) {
    pthread_mutex_lock(&m);
  } else {
    foo(n - 1);
  }
}
```
(a) 바닥 요약이 `(진입: {}, 반환: LockVar)`인 이유를 두 격자의 ⊥로 설명하라.
(b) 1차·2차 반복을 수행해 고정점 요약을 구하라.
(c) 상호 재귀(f가 g를, g가 f를 호출)에서는 이 반복을 어떻게 일반화하는가? (슬라이드 31)

**풀이.**
**(a)** live 격자는 ⊆(포함) 순서이므로 ⊥ = ∅ → 진입 바닥은 `{}`. available 격자는 ⊇(역포함) 순서이므로 ⊥ = **전체집합 LockVar**(모든 집합을 ⊇로 포함하는 가장 보수적 출발점) → 반환 바닥은 `LockVar`. 양쪽 다 "격자 바닥에서 위로 올라가는" Kleene 반복(강의 6)의 출발점이다.
**(b) 1차 (진입{}, 반환 LockVar 가정):**
- Live(후방): then — `lock(&m)` 위 `{}\{m}={}`. else — 호출 규칙 `({}\LockVar)∪{} = {}`. 진입 합류 `{}∪{}={}` → 진입 `{}`.
- Available(전방, 진입 `{}`): then — lock 후 `{}∪{m}={m}`. else — 호출 `({}\{})∪LockVar = LockVar`. 합류 `{m}∩LockVar = {m}` → 반환 `{m}`.
- **갱신 요약: (진입 {}, 반환 {m}).**
**2차 (진입{}, 반환{m} 가정):** else 호출 — live `({}\{m})∪{} = {}`, available `({}\{})∪{m} = {m}`. 합류 `{m}∩{m}={m}`. 결과 동일 → **고정점 (진입 {}, 반환 {m})**. 직관("재귀 끝에 결국 락을 획득한다", 슬28)과 일치. 교집합이 바닥값 LockVar를 걸러 내고 `{m}`만 남기는 과정에 주목.
**(c)** 순환(사이클)에 속한 **모든 함수의 요약을 동시에** 바닥에서 시작해, 같은 요약 집합으로 각 함수를 분석·갱신하기를 모든 요약이 고정점에 도달할 때까지 반복한다. 실무에서는 호출 그래프의 **SCC** 단위로 묶어 SCC 안은 동시 고정점 반복, SCC 사이는 위상 순서 상향식으로 처리한다(강의 10·11 연결).

### 문제 13-1 [계산·추적] (M, 슬라이드 18~22) ★
다음 함수에 추상 읽기/쓰기 집합 분석을 적용해 각 지점의 `(R, W)`를 구하고, `p`가 출력 매개변수인지 판정하라.
```c
void foo(int *p) {
  if (...) { *p = 42; }
  else { int x = *p; }
}
```

**풀이.**
- 진입: `({}, {})`.
- then `*p=42`: p∉r이므로 W에 추가 → `({}, {p})`.
- else `x=*p`: p∉w이므로 R에 추가 → `({p}, {})`.
- 합류: R은 합집합 `{}∪{p}={p}`, W는 교집합 `{p}∩{}={}` → `({p}, {})`.
- 반환 시 W={} → **p는 출력 매개변수가 아니다.**
이유: 한 경로(else)에서 p를 입력으로 읽으므로(R에 보존), 모든 경로에서 출력이라 단정 불가(W 교집합으로 비워짐).

### 문제 13-2 [개념·서술] (M, 슬라이드 26·28) ★
부분 함수의 성공/실패 반환값을 구분하기 위해 **정수 구간(interval) 도메인 대신 정수 집합(set) 도메인**을 쓰는 이유를, 다음 예로 설명하라: 실패 시 반환값 ∈ {−1, 2, 5}, 성공 시 {0}.

**풀이.**
- **집합 도메인**: 실패 `{−1,2,5}`, 성공 `{0}` → 두 집합이 **서로소** → "반환값이 0이면 성공, 아니면 실패"로 명확히 구분 가능 → `Result`로 변환 가능.
- **구간 도메인**: 실패 `[−1,5]`(흩어진 값을 최소~최대로 뭉침), 성공 `[0,0]`. 그런데 `[0,0] ⊆ [−1,5]` — **성공값 0이 실패 구간에 포함**되어, 반환값 0만 보고는 성공/실패를 구분할 수 없다.
구간은 "사이의 빈틈"을 메워 흩어진 값을 못 가르지만, 집합은 정확한 원소만 유지해 구분한다. 단 집합은 무한정 커질 수 있어 크기 k 제한·ℤ 올림이 필요(정밀도-비용 trade-off).

### 문제 13-3 [설계·응용] (M, 슬라이드 29~32)
출력 매개변수 `p`의 분석 결과에 따라 **튜플 / Result / Option** 중 무엇으로 변환할지 결정하는 규칙을 쓰고, 다음 각각이 어디에 해당하는지 답하라.
(a) 모든 경로에서 p에 씀, 실패 없음.
(b) 일부 경로만 p에 씀, 성공=0·실패=−1(구별됨).
(c) 일부 경로만 p에 씀, 성공·실패 둘 다 반환값 0(구별 안 됨).

**풀이.**
규칙: 반환 시 (i) **모든 쓰기집합이 p 포함** → must-output, 실패 없음 → **튜플**. (ii) **일부 쓰기집합만 p 포함 + p가 읽기집합엔 없음** → may-output(실패 가능); 성공 반환값이 실패값과 **구별되면 Result**, **구별 안 되면 Option**.
(a) → **튜플** `(반환, *p)`.
(b) → **Result** (성공 `Ok(*p)`, 실패 `Err(−1)`).
(c) → **Option** (반환값으론 구분 불가, 출력 유무로만: 쓴 경로 `Some`, 안 쓴 경로 `None`; 반환값 0은 튜플로 유지 → `(i32, Option<i32>)`).

### 문제 13-4 [계산·추적] (M, 슬라이드 44~48) ★
다음 I/O 코드에 출처·능력 제약식을 세우고 cubic으로 풀어 각 변수의 `⟦·⟧_o`(출처), `⟦·⟧_c`(능력)를 구하라.
```c
x = fopen(...);
y = stdin;
if (...) { z = x; } else { z = y; }
fgetc(z);
```

**풀이.**
제약: `file∈⟦x⟧_o`, `stdin∈⟦y⟧_o`; `z=x`→`⟦x⟧_o⊆⟦z⟧_o ∧ ⟦z⟧_c⊆⟦x⟧_c`; `z=y`→`⟦y⟧_o⊆⟦z⟧_o ∧ ⟦z⟧_c⊆⟦y⟧_c`; `fgetc(z)`→`read∈⟦z⟧_c`.
해: `⟦z⟧_o={file,stdin}`, `⟦z⟧_c={read}`; 능력이 z→x,y로 흐르므로 `⟦x⟧_c=⟦y⟧_c={read}`; `⟦x⟧_o={file}`, `⟦y⟧_o={stdin}`.
변환: x(단일 출처)→`File`, y→`Stdin`, z(다중 출처, 능력 read)→`Box<dyn Read>`.

### 문제 13-5 [개념·서술] (S, 슬라이드 45)
대입 `x = y`에서 **출처는 y→x 방향(`⟦x⟧_o ⊇ ⟦y⟧_o`)**인데 **능력 요구는 x→y 방향(`⟦x⟧_c ⊆ ⟦y⟧_c`)**으로 흐른다. 두 방향이 반대인 이유를 서브타이핑(공변/반변)으로 설명하라.

**풀이.**
- **출처(공변)**: 스트림 객체가 y에서 x로 *흐른다*. y가 가질 수 있는 출처는 x도 가질 수 있다 → 값의 흐름과 같은 방향(공변, covariant).
- **능력(반변)**: x에서 어떤 연산(예: read)을 하면, 그 객체는 실제로 원본 y이므로 **y도 그 능력을 갖춰야** 한다. 즉 사용처 x의 요구가 원본 y로 거슬러 흐른다(반변, contravariant). "능력이 더 많은 타입이 서브타입"이라는 규칙과 일치 — x로 쓰려면 y는 x가 요구하는 능력을 모두(더 많이 가진 건 OK) 갖춰야 한다. 함수 서브타이핑(인자는 반변, 결과는 공변)과 같은 구조.

### 문제 13-6 [계산·추적] (M, 슬라이드 20~21) ★ 〔신규〕
다음 두 함수에 읽기/쓰기 집합 분석을 단계별로 적용하고, 각각 p가 출력 매개변수인지 판정하라. 두 함수는 같은 두 문장을 **순서만 바꾼 것**이다.
```c
// (A)                     // (B)
void foo(int *p) {         int foo(int *p) {
  int x = *p;                *p = 42;
  *p = x + 1;                int x = *p;
}                            return x;
                           }
```

**풀이.**
**(A) 읽기가 먼저:**
- 진입 `({},{})`.
- `x = *p`: p∉w → R에 추가 → `({p},{})`.
- `*p = x+1`: **p가 이미 r에 있으므로 W에 추가하지 않음**(슬18 규칙) → `({p},{})`.
- 반환 시 W={} → **출력 매개변수 아님**. 직관: 기존 `*p` 값을 읽어 +1 하므로 p는 입력(기존 값이 필요) — "p를 받지 않으면 x의 값을 결정할 수 없다"(슬20).
**(B) 쓰기가 먼저:**
- 진입 `({},{})`.
- `*p = 42`: p∉r → W에 추가 → `({},{p})`.
- `x = *p`: **p가 이미 w에 있으므로 R에 추가하지 않음** → `({},{p})`.
- 반환 시 W={p} → **출력 매개변수**. 직관: 함수가 스스로 써넣은 42를 읽은 것이므로 p의 기존 값은 불필요 — "p를 받지 않아도 x의 값을 결정할 수 있다"(슬21).
**교훈**: R·W 규칙의 가드(`p∉w`일 때만 R에, `p∉r`일 때만 W에)가 **읽기/쓰기의 순서**를 정확히 반영하며, 순서가 출력 여부를 가른다.

### 문제 13-7 [개념·서술/설계] (M, 슬라이드 23~25) ★ 〔신규〕
다음 함수는 실제로는 출력 매개변수(성공 시에만 `*p`에 씀)이지만, 기본 `(R,W)` 분석은 이를 놓친다.
```c
int foo(int *p) {
  int x = -1;
  if (...) {
    *p = 42;
    x = 0;
  }
  return x;
}
```
(a) 기본 분석이 반환 시점에 어떤 `(R,W)`를 내며 왜 "출력 아님"으로 잘못 판정하는지 추적하라.
(b) **쓰기 집합 민감(write set sensitivity)** 분석의 상태 정의를 쓰고, 같은 코드에서 반환 시점의 상태를 구해 한계가 어떻게 해소되는지 보여라.
(c) 이 기법이 강의 10의 어떤 일반 아이디어의 사례인지 답하라.

**풀이.**
**(a)** then 가지 끝 `({},{p})`, if를 거치지 않는 암묵 경로는 `({},{})`. 합류 시 W는 교집합 `{p}∩{} = {}` → 반환 `({},{})`. W가 비어 "출력 아님"으로 판정 — 그러나 실제로는 성공 경로에서 p에 쓴다. **부분 함수(성공/실패)의 두 경로가 합류에서 뭉개진 것**이 원인(슬23).
**(b)** 상태를 단일 `(R,W)`가 아니라 **사상 `W → R`**(가능한 쓰기 집합마다 읽기 집합을 따로 유지)로 둔다(슬24). 추적: then 끝은 `{p}: {}`, 통과 경로는 `{}: {}`. 합류에서 **두 항목을 뭉개지 않고 모두 유지** → 반환 시점 상태 = `{ {}: {}, {p}: {} }`. 이제 분석은 (i) W={p}인 항목이 존재 → **p는 (성공 경로의) 출력 매개변수**, (ii) W={}인 항목도 존재 → **실패 가능(부분 함수)** 임을 동시에 안다. 이후 정수 집합 도메인(슬26~28)으로 성공/실패 반환값을 구분해 Result/Option을 결정한다.
**(c)** 합류에서 정보를 뭉개지 않고 갈래별로 분리 유지하는 **경로/문맥 민감(sensitivity)** 의 한 형태(강의 10) — 구분 기준이 "쓰기 집합"인 경우다. 정밀도↑·비용↑ trade-off도 동일하다.

## 강의 14 — Pointer Analysis 1 (Andersen, Steensgaard)

### 문제 14-1 [계산·추적] (M, 슬라이드 6~9) ★
다음 코드에 **Andersen 분석**을 적용해 각 변수의 points-to 집합을 구하라.
```
x = &a;
y = &x;
z = *y;
*x = z;
```

**풀이.**
제약: `a∈[x]`; `x∈[y]`; `z=*y`: ∀c. c∈[y]⇒[c]⊆[z] → x∈[y]이므로 `[x]⊆[z]`; `*x=z`: ∀c. c∈[x]⇒[z]⊆[c] → a∈[x]이므로 `[z]⊆[a]`.
해: `[x]={a}`, `[y]={x}`, `[z]⊇[x]={a}` → `[z]={a}`, `[a]⊇[z]={a}` → `[a]={a}`.
즉 pt(x)={a}, pt(y)={x}, pt(z)={a}, pt(a)={a}.

### 문제 14-2 [계산·추적] (M, 슬라이드 12~16) ★
문제 14-1과 같은 코드의 첫 세 줄(`x=&a; y=&x; z=*y;`)에 **Steensgaard 분석**을 적용하고, Andersen 결과(pt(y)={x})와 비교해 어느 쪽이 더 정밀한지 답하라.

**풀이.**
Steensgaard 제약: `⟦x⟧=&⟦a⟧`, `⟦y⟧=&⟦x⟧`, `z=*y`⟹`⟦y⟧=&⟦z⟧`.
`⟦y⟧=&⟦x⟧`이자 `&⟦z⟧`이므로 `&⟦x⟧=&⟦z⟧` → **⟦x⟧=⟦z⟧ 단일화**. 따라서 pt(y)={x,z}, pt(x)=pt(z)={a}.
**비교**: Andersen은 pt(y)={x}(정확), Steensgaard는 pt(y)={x,z}(x와 z를 합쳐 거침). **Andersen이 더 정밀**. Steensgaard는 대입을 양방향(등식)으로 보아 불필요하게 셀을 합치지만 단일화로 거의 선형 시간.

### 문제 14-3 [개념·서술] (F, 슬라이드 11·16·26)
Andersen과 Steensgaard 분석을 (1) 대입을 보는 방식, (2) 푸는 알고리즘, (3) 시간 복잡도, (4) 정밀도 관계의 네 축으로 비교하라. 또 임의의 프로그램에서 `pt_Steensgaard(x) ⊇ pt_Andersen(x)`가 항상 성립함을 직관적으로 논하라.

**풀이.**
| 축 | Andersen | Steensgaard |
|---|---|---|
| 대입 | 단방향 포함 `[y]⊆[x]` | 양방향 등식 `⟦x⟧=⟦y⟧` |
| 알고리즘 | cubic(워크리스트) | 단일화(union-find) |
| 복잡도 | O(n³) | 거의 선형 O(n·α(n)) |
| 정밀도 | 높음 | 낮음 |
**포함 관계**: Steensgaard는 `x=y`를 등식으로 보아 두 변수(와 그들이 가리키는 셀)를 합친다. 합치면 한쪽만 가리키는 것도 양쪽이 가리킨다고 보게 되어 pt가 **커진다**. Andersen은 단방향이라 필요한 흐름만 반영한다. 따라서 Steensgaard의 pt는 항상 Andersen의 pt를 포함(같거나 큼). 둘 다 sound, Andersen이 더 tight.

### 문제 14-4 [개념·서술/증명] (M, 슬라이드 21~22) ★
함수 포인터가 있을 때 **제어 흐름 분석과 points-to 분석이 상호 의존**함을 설명하고, Andersen 방식이 이 둘을 **하나의 제약 시스템으로 통합**해 동시에 푸는 원리를 (강의 11의 CFA 규칙과 비교해) 논하라.

**풀이.**
- **상호 의존**: `(*y)()` 같은 호출의 대상은 `pt(y)`(어떤 함수 셀을 가리키나)가 정해야 알 수 있다(CFA는 pt 필요). 반대로 그 호출로 인자가 매개변수로 흐르는 points-to 전파는 호출 대상을 알아야 한다(pt는 CFA 필요). 따라서 둘은 순환 의존.
- **통합 원리**: 함수를 **셀의 일종(토큰)**으로 취급하면, 강의 11의 CFA 제약 규칙(`fn f ⟹ f∈[f]`, 호출 `x=y(z) ⟹ ∀f. f∈[y]⇒([z]⊆[a_f]∧[RET_f]⊆[x])`)이 Andersen 제약과 **글자 그대로 같은 형태**가 된다(차이는 `[·]`가 셀 집합인 것뿐). 세 형태(`t∈x`, `x⊆y`, `t∈x⇒y⊆z`)뿐이므로 강의 11의 cubic 알고리즘이 통합 제약을 한 번에 풀어, pt와 CFA가 **하나의 고정점 계산**으로 동시에 나온다.

### 문제 14-5 [개념·서술] (S, 슬라이드 3~4) 〔신규〕
**할당 지점 추상화(allocation-site abstraction)**를 정의하고 다음에 답하라.
(a) 런타임 메모리 셀은 무한할 수 있는데 추상 셀 집합 `Cell`이 유한한 이유.
(b) 이 추상화가 잃는 정밀도의 대표적 예.
(c) points-to 결과로 앨리어스를 판정하는 규칙과, "may"와 "must not"의 비대칭.

**풀이.**
정의: 각 프로그램 변수 x마다 추상 셀 `x`, 프로그램의 각 `alloc` **발생 위치**마다 추상 셀 `alloc-i`를 두고, 각 추상 셀이 "그 소스 위치에서 할당된 런타임 셀들의 집합"을 나타내게 한다.
**(a)** 추상 셀은 런타임 인스턴스가 아니라 **소스 위치**(변수 선언·alloc 줄)로 분류된다. 프로그램 텍스트는 유한하므로 위치도, 따라서 `Cell`도 유한 — 무한 구체를 유한 추상으로 접는 강의 5~6의 추상화 철학의 메모리판.
**(b)** **루프 안 `alloc`**: 매 반복 새 메모리가 생기지만 전부 같은 `alloc-i` 하나로 뭉개져 서로 구분 불가 → 그 셀은 여러 런타임 셀의 **요약 셀**이 되어 정밀도가 떨어진다(강의 15의 strong update 금지 사유와 직결). 더 정밀하게 하려면 호출 문맥별 분리(강의 10의 문맥 민감) 등이 필요.
**(c)** `pt(x) ∩ pt(y) ≠ ∅` ⟹ x,y는 **앨리어스일 수 있음**(may). 반대로 `pt(x) ∩ pt(y) = ∅`이면 **절대 앨리어스가 아님**(확실한 부정 정보). 과근사이므로 "겹친다"는 가능성일 뿐이지만 "안 겹친다"는 확정이다 — may 분석의 결과는 부정 방향으로만 확신을 준다.

### 문제 14-6 [계산·추적] (F, 슬라이드 22~25) ★ 〔신규〕
함수 포인터가 섞인 다음 코드에 **CFA가 통합된 Andersen 분석**의 제약식을 세우고 풀어라. 이어서 같은 코드를 Steensgaard로 풀었을 때의 차이를 답하라.
```
fn f(a) {}
fn g(b) {}
x = f;  y = g;
if ... { z = &x; } else { z = &y; }
w = *z;
u = &v;
w(u);
```

**풀이.**
**제약(Andersen + CFA, 슬22~23):**
- `fn f`: f∈⟦f⟧; `fn g`: g∈⟦g⟧.
- `x=f`: ⟦f⟧⊆⟦x⟧; `y=g`: ⟦g⟧⊆⟦y⟧.
- `z=&x`: x∈⟦z⟧; `z=&y`: y∈⟦z⟧.
- `w=*z`: ∀c. c∈⟦z⟧ ⇒ ⟦c⟧⊆⟦w⟧.
- `u=&v`: v∈⟦u⟧.
- `w(u)`: ∀h. h∈⟦w⟧ ⇒ ⟦u⟧⊆⟦a_h¹⟧.
**풀이 과정:** ⟦x⟧={f}, ⟦y⟧={g}, ⟦z⟧={x,y}. `w=*z` 조건부가 x,y∈⟦z⟧로 발동 → ⟦x⟧∪⟦y⟧⊆⟦w⟧ → **⟦w⟧={f,g}** (pt가 CFA를 결정: `w(u)`의 호출 대상은 f,g 둘 다). 호출 규칙이 f,g∈⟦w⟧로 발동 → ⟦u⟧={v}가 두 매개변수로 전파 → **⟦a⟧=⟦b⟧={v}**.
points-to가 제어 흐름을 정하고(1→2), 제어 흐름이 다시 points-to를 정하는(2→3) 순환 의존이 한 제약 시스템 안에서 자연히 풀린다(슬21의 해소).
**Steensgaard 비교(슬25):** `x=f`, `y=g`가 등식이라 f,g,x,y,w의 항이 모두 **단일화**되어 함수 성분을 공유 → func(f)=func(g)=func(x)=func(y)=func(w)={f,g} — 어떤 함수 변수를 호출하든 f,g 둘 다 가능하다고 본다. 매개변수도 합쳐져 ⟦u⟧=⟦a⟧=⟦b⟧=(&⟦v⟧,_). 이 예에선 최종 pt(u)=pt(a)=pt(b)={v}로 Andersen과 우연히 같지만, 함수 셀들이 한 덩어리로 합쳐지는 정밀도 손실이 내부에서 일어났다. 대신 거의 선형 시간.

## 강의 15 — Pointer Analysis 2 (Flow-Sensitive, Strong/Weak Update)

### 문제 15-1 [개념·서술] (M, 슬라이드 8~14) ★
**강한 갱신(strong update)과 약한 갱신(weak update)**을 정의하고, `*p = e`에서 strong update가 **건전(sound)**하기 위한 정확한 조건을 쓰라. 단순히 "p가 단일 추상 셀을 가리킴(`pt(p)={c}`)"만으로 strong update를 하면 왜 unsound할 수 있는지 예와 함께 설명하라.

**풀이.**
- **strong update**: 대상 셀의 값을 새 값으로 **덮어쓰기** `σ[c↦v]`. 정밀.
- **weak update**: 새 값을 기존 값과 **합치기** `σ[c↦σ(c)⊔v]`. 보수적·안전.
- **건전 조건**: 추상 셀 c가 **단 하나의 런타임 셀**을 확실히 나타낼 때만 strong update 가능. 그 외엔 weak update.
- **`pt(p)={c}`만으론 부족**: 추상 셀 c가 여러 런타임 셀을 뭉친 **요약 셀**일 수 있다. 예) 루프 안 `x=alloc()`는 매 반복 새 메모리지만 추상적으론 모두 `alloc-0`. `pt(x)={alloc-0}`(단일 추상 셀)이라 strong update하면, 루프 후 `*x=1`이 **모든** 런타임 인스턴스를 1로 덮어 — 그런데 그중 첫 메모리(다른 포인터 y가 가리킴)는 실제로 0이라 unsound. 그래서 "단일 *추상* 셀"이 아니라 "단일 *런타임* 셀"이 조건이어야 한다.

### 문제 15-2 [계산·추적] (M, 슬라이드 11~12) ★
상태 `x:[1,1], y:[2,2]`에서 `z`가 `{x,y}`를 가리킨다. `*z = 3` 이후 x, y의 추상값을 strong/weak 규칙(슬11)에 따라 구하라.

**풀이.**
z가 가리키는 셀이 **여럿**(`{x,y}`)이므로 **weak update**.
- x: `[1,1] ⊔ [3,3] = [1,3]`.
- y: `[2,2] ⊔ [3,3] = [2,3]`.
(둘 중 하나만 실제로 3이 되지만 어느 것인지 모르므로 둘 다 "기존 또는 3"으로 합쳐 sound 유지. 무조건 덮어쓰면 둘 다 [3,3]이 되어 x=1, y=2 가능성을 잃어 unsound.)

### 문제 15-3 [계산·추적/개념] (F, 슬라이드 19~22) ★
다음 재귀 함수에서 지역 변수 x에 strong update를 적용하면 unsound함을 보이고, 올바른 결과(weak update)를 구하라.
```c
fn foo() {
  let x = 0;
  let p = &x;
  if ... { foo(); } else { x = 1; }
}
foo();
```

**풀이.**
재귀 함수의 지역 변수 x는 **여러 활성화(activation)가 동시 존재**하면 여러 런타임 셀을 나타낸다(요약 셀). 안쪽 호출에서 x=1이 되어도 **바깥 활성화의 x는 0**이다.
- **strong update 시**: x를 1로 덮어 "x는 반드시 [1,1]" → 바깥 x가 실제 0인데 누락 → **unsound**.
- **올바른(weak) 결과**: 재귀 함수이므로 x에 weak update → `[0,0]⊔[1,1]=[0,1]`. "바깥 x=0, 안쪽 x=1 가능"을 모두 포함 → sound.
규칙(슬21): strong update는 **비재귀 함수의 지역 변수**(단일 런타임 셀 보장)에만 허용. 재귀 여부는 호출 그래프 SCC(강의 11)로 판정.

### 문제 15-4 [설계·응용] (S, 슬라이드 17)
절차간 흐름 감각 포인터 분석에서, 함수 호출 시 **인자 외에 어떤 셀들의 값을 함수 경계 너머로 전달**해야 하며, 왜 "주소가 취해진(address-taken) 변수"만 전달하면 충분한지 설계·논증하라.

**풀이.**
함수는 포인터를 통해 인자가 아닌 메모리(호출자의 변수, 힙)도 바꿀 수 있으므로, 호출 시 **주소가 취해진 변수와 힙 셀의 값**도 callee에 넘기고, 반환 시 (callee가 바꿨을 수 있으니) 되받아야 한다. **주소가 안 취해진 변수**(누구도 `&`로 주소를 안 딴 변수)는 포인터로 가리킬 방법이 없어 callee가 건드릴 수 없다 → 전달 불필요. 따라서 address-taken 셀만 넘기면 건전하면서 효율적이다.

### 문제 15-5 [계산·추적] (M, 슬라이드 4~7) 〔신규〕
흐름 감각 포인터 분석의 추상 도메인을 (구간 × 𝒫(Cell)) 곱으로 두고, 다음 코드의 각 지점 상태를 추적하라. 특히 `w = *z`의 fetch가 어떻게 계산되는지 보여라.
```
x = 1;
y = 2;
if ... { z = &x; } else { z = &y; }
w = *z;
```

**풀이.**
추상값 = `(구간, 셀 집합)` 쌍 — 정수이면 구간 성분, 포인터이면 points-to 성분이 의미를 가진다(슬4).
- `x = 1` 후: `x: ([1,1], ⊥)`.
- `y = 2` 후: `y: ([2,2], ⊥)`.
- then `z = &x` 후: `z: (⊥, {x})`; else `z = &y` 후: `z: (⊥, {y})`.
- 합류: 성분별 join → `z: (⊥, {x}∪{y}) = (⊥, {x,y})` — z는 x **또는** y를 가리킨다.
- `w = *z` (fetch): z가 가리킬 수 있는 모든 셀의 값을 join — `σ(x) ⊔ σ(y) = ([1,1],⊥) ⊔ ([2,2],⊥) = ([1,2], ⊥)` → **`w: ([1,2], ⊥)`** (w는 1 또는 2).
**핵심**: 역참조 **읽기**는 후보 셀 값들을 ⊔로 합쳐도 항상 안전하다(가능성을 모두 포함). 위험한 것은 역참조 **쓰기** — 거기서 strong/weak 구분(슬8~14, 문제 15-1~15-2)이 필요해진다.

### 문제 15-6 [개념·서술] (F, 슬라이드 8·11·14·21) ★ 〔신규〕
강의 15는 간접 대입 `*e₁ = e₂`의 update 규칙을 **세 번에 걸쳐 수정**한다. 각 단계의 규칙, 그 규칙을 깨뜨리는 반례, 최종 규칙을 순서대로 정리하라.

**풀이.**
**1단계 (슬8, Incorrect) — 무조건 덮어쓰기**: `update(σ,(_,C),v) = σ[c₁↦v,…,cₙ↦v]` (가리킬 수 있는 모든 셀에 덮어씀).
- 반례(슬10): z가 {x,y}를 가리킬 때 `*z=3`은 실제로 둘 중 **하나만** 바꾸는데, 이 규칙은 둘 다 [3,3]으로 → x=1, y=2 가능성 누락 → **unsound**.
**2단계 (슬11, Still Incorrect) — 단일 추상 셀이면 strong, 다중이면 weak**: `C={c}`이면 덮어쓰고, 그 외엔 `σ[c↦σ(c)⊔v]`.
- 반례(슬13): 루프 안 `x=alloc()` 후 `*x=1`. `pt(x)={alloc-0}` 단일 추상 셀이지만 alloc-0은 매 반복의 메모리를 뭉친 **요약 셀** — 첫 반복의 메모리(y가 가리킴)는 여전히 0인데 [1,1]로 덮어 → **unsound**.
**3단계 (슬14→슬21, Correct) — 최종 규칙**:
`update(σ,(_,C),v) = σ[x↦v]` ⟺ `C={x}`이고 **x가 비재귀 함수의 지역 변수**(단일 런타임 셀 보장); 그 외(다중 셀, 할당 셀, 재귀 함수의 변수, 전역 등 요약 셀 가능성)는 모두 weak update `⨆_{c∈C} σ[c↦σ(c)⊔v]`.
- 절차간 확장에서 "재귀 함수의 지역 변수"가 추가로 배제되는 이유(슬19~22): 여러 활성화가 동시에 존재해 한 추상 셀이 여러 런타임 셀을 나타내기 때문(문제 15-3).
**서사**: 조건이 "무조건 → 단일 추상 셀 → 단일 런타임 셀"로 강화되는 과정 자체가, **건전성 조건은 추상 수준이 아니라 구체(런타임) 수준에서 진술되어야 한다**는 교훈이다.

## 강의 16 — Relational Analysis 1 (Linear Equalities, Polyhedra)

### 문제 16-1 [개념·서술] (M, 슬라이드 2~3)
**비관계형 vs 관계형 분석**의 차이를 코드 예로 설명하고, 관계형 분석이 비관계형이 놓치는 어떤 사실을 잡아내는지 보여라.

**풀이.**
비관계형은 각 변수를 따로(구간 등) 추적해 변수 간 관계를 잃는다. 예: `y=x; z=(x==y);`에서 비관계형은 x,y 각각 [-∞,∞]만 알아 x==y를 모르고 z∈{0,1}로 둔다. 관계형은 `y=x`로 **`x=y`라는 관계**를 기억해 x==y가 항상 참 → z=1로 정확히 판단한다. 관계형은 "x=y", "z<x" 같은 변수 간 관계를 표현·추적한다.

### 문제 16-2 [증명·유도] (M, 슬라이드 21·38) ★
선형 **등식** 도메인은 위드닝 없이 join만으로 분석이 종료되지만, 선형 **부등식(다면체)** 도메인은 진짜 위드닝이 필요하다. 두 경우의 **격자 높이**를 근거로 이 차이를 증명하라.

**풀이.**
- **등식 도메인**: n변수에서 상태는 등식 개수가 0(⊤)부터 n개(점)까지, 그리고 ⊥. join을 반복하면 공통 등식만 남아 등식 개수가 **단조 감소**한다. 사슬 길이 ≤ n+2(유한 높이)이므로 임의의 증가 사슬이 유한 단계에서 멈춘다 → join만으로 고정점 도달, **위드닝 불필요**.
- **부등식 도메인**: 부등식 개수에 제한이 없고, 경계가 `x≤1, x≤2, x≤3, …`처럼 **무한히 변할 수 있어** 격자 높이가 무한. join 반복이 영영 안 멈출 수 있다(예: 루프가 영역을 계속 넓힘). 따라서 "안정적 부등식만 유지하고 변하는 경계는 ∞로 보내는" **위드닝으로 강제 종료**해야 한다.

### 문제 16-3 [계산·추적] (M, 슬라이드 19~20) ★
선형 등식 도메인에서 두 상태의 join을 구하라.
- s1: `y + z = 0 ∧ y − z = 2` (직선)
- s2: `y + z = 2 ∧ y − z = 0` (직선)

**풀이.**
기하 표현: s1은 P=(0,1,−1), 방향 U0=(1,0,0); s2는 P'=(0,1,1), U'0=(1,0,0).
join: 점 P=(0,1,−1), 방향 기저 = {U0=(1,0,0), U'0=(1,0,0), P'−P=(0,0,2)}. 정규화하면 독립 방향은 (1,0,0)과 (0,0,1) 두 개(x,z 자유).
→ y만 고정: 두 직선의 공통 등식을 구하면 **y=1**. (s1·s2 모두 y=1을 만족: s1에서 (y+z)+(y−z)=2y=2→y=1; s2도 2y=2→y=1.)
**join = `y = 1`**(평면). 개별 z 관계는 버려지고 공통 관계 y=1만 남음.

### 문제 16-4 [계산·추적] (M, 슬라이드 24~27)
선형 등식 도메인에서 다음 대입을 처리하라.
(a) 상태 `x + y = 1`, 대입 `x = x + 1`. (가역)
(b) 상태 `x + y = 0 ∧ x + z = 0`, 대입 `x = y − z`. (비가역)

**풀이.**
(a) **가역**(우변에 x). 옛 x = 새 x − 1. 상태의 x를 (x−1)로 치환: `(x−1)+y=1` → **`x+y=2`**.
(b) **비가역**(우변에 x 없음). 정규화로 x 없는 등식 분리: 두 등식을 빼면 `y−z=0`. x 포함 옛 등식 버리고 새 등식 x=y−z 추가 → `x−y+z=0 ∧ y−z=0`. y=z이므로 → **`x=0 ∧ y−z=0`**.

### 문제 16-5 [개념·서술/증명] (F, 슬라이드 29·36) ★
다면체 도메인이 **구간과 등식 도메인을 모두 포함(subsume)**함을 보이고, 다면체의 join(볼록 껍질)이 왜 **과근사**가 될 수 있는지 설명하라.

**풀이.**
- **포함**: 구간 `x∈[l,h]`는 부등식 `x≤h ∧ −x≤−l`로, 등식 `e=b`는 `e≤b ∧ −e≤−b`로 표현된다. 즉 다면체 도메인의 부등식 연립이 구간·등식을 특수 경우로 담는다 → `다면체 ⊇ 등식 ⊇ 구간`.
- **join 과근사**: 다면체 join은 두 영역을 모두 포함하는 **가장 작은 볼록 집합(볼록 껍질)**이다. 두 다면체의 합집합이 볼록이 아니면(예: 떨어진 두 영역), 볼록 껍질은 그 **사이를 메워** 실제 합집합보다 넓어진다. 다면체 도메인은 볼록 영역만 표현하므로 비볼록 합집합을 정확히 못 담아 과근사가 생긴다(하지만 sound).

### 문제 16-6 [계산·추적] (M, 슬라이드 22~23) 〔신규〕
선형 등식 도메인의 **control-sensitivity**: 현재 상태가 `x + 2y = 1`일 때, 다음 각 분기 조건을 통과한 직후의 상태를 구하라.
(a) `if (2x + 4y == 2)` (b) `if (x − y == 4)` (c) `if (x + 2y == 2)` (d) `if (x < y)`

**풀이.**
조건이 **선형 등식**이면 상태에 추가하고 정규화한다(슬22).
(a) `2x+4y=2`는 `x+2y=1`의 2배 — **동치(새 정보 없음)** → 상태 그대로 `x+2y=1`.
(b) `x−y=4`는 독립 등식 → 추가해 연립 `x+2y=1 ∧ x−y=4`를 풀면 (둘째에서 x=y+4를 첫째에 대입: y+4+2y=1 → 3y=−3) → **`x=3 ∧ y=−1`** (점으로 좁혀짐).
(c) `x+2y=2`는 기존 `x+2y=1`과 **모순**(같은 식이 1이자 2일 수 없음) → **⊥**. 이 분기는 도달 불가(죽은 코드)로 판정.
(d) `x<y`는 **부등식** — 등식 도메인은 부등식을 표현할 수 없다(표현력 한계). 현재 등식들과 명백히 모순도 아니므로 **정보 추가 없이 통과**(상태 유지 `x+2y=1`). 이 한계가 부등식(다면체) 도메인(슬29~)이 필요한 이유이며, 다면체 도메인의 control-sensitivity(슬40)는 부등식 조건도 직접 추가할 수 있다.

### 문제 16-7 [계산·추적] (M, 슬라이드 39·42~43) ★ 〔신규〕
다면체 도메인에서 다음 세 연산을 수행하라.
(a) **위드닝**: s1 = `2y ≤ x−2 ∧ 2y ≤ −x+6 ∧ y ≥ 0`, s2 = `2y ≤ x−2 ∧ 2y ≤ −x+10 ∧ y ≥ 0`일 때 `s1 ∇ s2`.
(b) **가역 대입**: 상태 `2y ≤ x−2 ∧ 2y ≤ −x+6 ∧ y ≥ 0`에 `x = x + 4`.
(c) **비가역 대입**: 상태 `y ≥ 1 ∧ y ≥ −x+5 ∧ y ≤ x+1`에 `y = x + 1`.

**풀이.**
**(a)** 위드닝 원리: **안정적인(두 상태에서 변하지 않는) 부등식만 유지**, 움직이는 부등식은 버림(∞로).
- `2y≤x−2`: 양쪽 동일 → 유지. `y≥0`: 양쪽 동일 → 유지.
- `2y≤−x+6` → `2y≤−x+10`: 경계가 느슨해짐(루프가 영역을 넓히는 중) → **버림**.
→ **`s1 ∇ s2 = 2y ≤ x−2 ∧ y ≥ 0`** (위쪽 경계가 열린 무한 영역; 종료 보장).
**(b)** 가역(우변에 x, 계수 1≠0). 옛 x = 새 x − 4를 모든 부등식에 치환:
- `2y ≤ (x−4)−2 = x−6`, `2y ≤ −(x−4)+6 = −x+10`, `y≥0` 유지.
→ **`2y ≤ x−6 ∧ 2y ≤ −x+10 ∧ y ≥ 0`** — 다면체가 x축 방향으로 +4 평행이동(정보 보존).
**(c)** 비가역(우변에 y 없음). 절차: ① 옛 부등식들에서 y를 소거해 y 무관 정보 추출 — `y≥−x+5`와 `y≤x+1`을 결합하면 `−x+5 ≤ y ≤ x+1` → `−x+5 ≤ x+1` → **`x ≥ 2`** (또한 `y≥1`과 `y≤x+1`에서 `x≥0`은 `x≥2`에 흡수). ② y 관련 옛 부등식 폐기. ③ 새 관계 `y = x+1`을 `y≤x+1 ∧ y≥x+1`로 추가.
→ **`x ≥ 2 ∧ y = x + 1`** — 2차원 영역이 직선의 반직선 부분으로 좁혀짐. 옛 y 범위 정보는 일부 잃지만 새 관계는 정확.

## 강의 17 — Relational Analysis 2 (Octagon, DBM)

### 문제 17-1 [개념·서술] (M, 슬라이드 2~5)
**팔각형(octagon) 도메인**이 허용하는 부등식 형태를 쓰고, 표현력·비용 면에서 구간·다면체 사이 어디에 위치하는지 설명하라. 왜 "팔각형"이라 불리는가?

**풀이.**
허용 형태: `±x ± y ≤ c`(계수 ∈ {−1,0,1}), 즉 변수 하나 `±x≤c`(구간 경계)와 변수 둘의 합/차 `±x±y≤c`. 표현력·비용 위계: **구간 ⊊ 팔각형 ⊊ 다면체**. 구간보다 변수 간 차/합 관계를 더 잡아 정밀하지만, 다면체처럼 임의 계수(`3x+5y`)는 못 다뤄 표현력은 약한 대신 **다항 시간(DBM+그래프)**으로 훨씬 싸다. 두 변수 영역을 그리면 구간 사각형의 네 모서리를 45° 대각선으로 깎은 **8변 도형(팔각형)**이라 그 이름이 붙었다.

### 문제 17-2 [설계·유도] (M, 슬라이드 11~14) ★
팔각형 제약 `x + y ≤ c`(합)와 `x ≤ c`(단일)를, 변수를 `x⁺(=+x), x⁻(=−x)`로 분리한 **확장 DBM의 차이 제약**으로 변환하라. 왜 이 분리로 모든 팔각형 제약이 차이 제약이 되는지 논하라.

**풀이.**
- `x + y ≤ c`: y⁻=−y이므로 `x − (−y) = x⁺ − y⁻ ≤ c`. (일관성 켤레로 `y⁺ − x⁻ ≤ c`도)
- `x ≤ c`: `x − (−x) = x⁺ − x⁻ = 2x ≤ 2c`.
- (참고 `x − y ≤ c` → `x⁺ − y⁺ ≤ c`.)
**원리**: 각 변수를 +버전·−버전으로 쪼개면, 합(`x+y`)은 `x⁺−y⁻`처럼 한 변수의 −버전을 빼는 **차이**가 되고, 부호 붙은 단일 변수도 `x⁺−x⁻` 차이가 된다. 따라서 모든 `±x±y≤c`가 확장 변수(2n개)의 차이 제약으로 표현되어, 차이 제약 전용 도구(DBM·포텐셜 그래프·최단경로)를 그대로 쓸 수 있다.

---

### 문제 17-3 [증명·유도] (M, 슬라이드 17~18) ★
팔각형 상태가 **공집합(⊥)**일 필요충분조건이 "포텐셜 그래프에 음수 가중치 사이클이 있음"임을 직관적으로 증명하고, 어떤 알고리즘으로 검출하는지 답하라. `x−y≤1 ∧ x−y≥2`가 ⊥임을 그래프로 보여라.

**풀이.**
**증명(직관).** 사이클 `v→...→v`의 가중치 합이 차이 제약을 따라 더해지면 `v − v ≤ (사이클 합)`, 즉 `0 ≤ (사이클 합)`이 도출된다. 사이클 합이 음수면 `0 ≤ (음수)`라는 모순 → 해가 없음(⊥). 역으로 모든 사이클이 비음수면 일관된 포텐셜(해)이 존재한다(차이 제약 시스템-최단경로 동치 정리).
**검출**: Bellman–Ford 알고리즘(음수 사이클 탐지, O(VE)).
**예**: `x−y≤1`(y→x 가중치 1)과 `x−y≥2`(=`y−x≤−2`, x→y 가중치 −2). 사이클 x→y→x 합 = `−2 + 1 = −1 < 0` → 음수 사이클 → ⊥. (직접: (x−y)+(y−x)=0 ≤ 1+(−2)=−1, 모순.)

---

### 문제 17-4 [계산·추적] (M, 슬라이드 23~24)
DBM 표현에서 다음을 칸별 연산으로 구하라.
(a) `{x−y≤1, z−w≤2} ⊔ {x−y≤2, z−w≤1}` (join)
(b) `{x−y≤1, z−w≤2} ∇ {x−y≤2, z−w≤2}` (위드닝)

**풀이.**
(a) **join = 칸별 max**(느슨한 상한): x−y는 max(1,2)=2, z−w는 max(2,1)=2 → **`{x−y≤2, z−w≤2}`**.
(b) **위드닝**: 상한이 안 늘면 유지, 늘면 ∞. x−y는 1→2로 **늘어남 → ∞**(버림); z−w는 2→2 **안정 → 유지**. → **`{z−w≤2}`** (x−y 제약 폐기).

### 문제 17-5 [개념·서술] (S, 슬라이드 19~22)
DBM **정규화(normalization)**가 무엇이며 왜 필요한지 설명하라. 정규화가 어떤 그래프 알고리즘과 동치인지, `x−y≤1 ∧ y−z≤2`에서 정규화가 어떤 함의 제약을 추가하는지 답하라.

**풀이.**
같은 해집합을 여러 DBM이 표현할 수 있으므로(함의된 제약을 적었느냐에 따라), 순서·동치 비교를 정확히 하려면 **표준형**이 필요하다. 정규화 = 모든 변수 쌍의 **가장 강한(최단경로) 차이 제약을 명시적으로 채우기** = 포텐셜 그래프의 **최단경로 닫힘(Floyd–Warshall, O(n³))**. 그러면 같은 해집합은 유일한 정규 DBM이 되어, 순서가 **칸별 비교**(`m_ij ≤ n_ij`)로 정확히 판정된다.
예: `x−y≤1`과 `y−z≤2`를 더하면 **`x−z≤3`**이 함의되어 추가된다(경로 x→y→z 합성).

---

### 문제 17-6 [계산·추적] (M, 슬라이드 13~16) 〔신규〕
변수 `Var = {x, y}`에 대한 팔각형 제약 `x − y ≤ 2`, `x + y ≤ 3`, `x ≥ 1`을 확장 변수 `V = {x⁺, x⁻, y⁺, y⁻}`의 차이 제약으로 모두 변환하라(일관성 켤레 포함). 또 DBM의 **일관성(coherence)** 조건 `m_ij = m_{j̄ī}`가 무엇을 보장하는지 설명하라.

**풀이.**
변환표(슬14)에 따라:
- `x − y ≤ 2` → `x⁺ − y⁺ ≤ 2` 와 켤레 `y⁻ − x⁻ ≤ 2`.
- `x + y ≤ 3` → `x⁺ − y⁻ ≤ 3` 와 켤레 `y⁺ − x⁻ ≤ 3`. (y⁻=−y이므로 x−(−y)=x+y)
- `x ≥ 1` ⟺ `−x ≤ −1` → 단일 제약 규칙으로 `x⁻ − x⁺ ≤ 2·(−1) = −2`. (x⁻−x⁺ = −2x ≤ −2 ⟺ x ≥ 1)
총 5개 차이 제약이 4×4 확장 DBM의 칸에 들어가고, 4노드(x⁺,x⁻,y⁺,y⁻) 포텐셜 그래프의 가중 간선이 된다(슬16).
**일관성**: 하나의 팔각형 제약은 확장 DBM에서 **두 칸에 중복** 표현된다(예: `x+y≤3`은 `x⁺−y⁻≤3`이자 `y⁺−x⁻≤3` — 같은 제약을 변수 순서만 바꿔 쓴 것). `m_ij = m_{j̄ī}`는 이 켤레 쌍이 항상 같은 값을 갖도록 해 "같은 제약의 두 표현이 서로 어긋나지 않음"을 보장한다. 팔각형 DBM의 모든 연산은 이 대칭을 유지해야 한다.

### 문제 17-7 [계산·추적] (M, 슬라이드 25~30) ★ 〔신규〕
팔각형 DBM 위에서 다음 세 연산을 수행하라.
(a) **분기 조건**: 상태 `x−y≤2`에 조건 ① `x−y≤3`, ② `x−y≤1`을 각각 반영.
(b) **가역 대입**: 상태 `x−y≤1 ∧ x≤2 ∧ z−x≤3`에 `x = x + 1`.
(c) **비가역 대입**: 상태 `x−y≤1 ∧ z−w≤2`에 `x = y + 5`.

**풀이.**
**(a)** 조건 반영 = 해당 칸을 `min(기존, c)`로(meet처럼, 슬25):
- ① `min(2, 3) = 2` → **변화 없음**(이미 더 강한 제약 보유).
- ② `min(2, 1) = 1` → **`x−y≤1`**로 좁아짐(정밀화). 반영 후엔 음수 사이클 검사로 ⊥ 여부 확인.
**(b)** 가역 `x = x + c` (c=1): x가 **양의 부호**로 든 제약은 상한 +c, **음의 부호**로 든 제약은 상한 −c(슬27~28):
- `x−y≤1` → `x−y≤2` (x 증가로 차이 증가).
- `x≤2` → `x≤3`.
- `z−x≤3` → `z−x≤2` (x 증가로 z−x 감소).
→ **`x−y≤2 ∧ x≤3 ∧ z−x≤2`** — x 관련 상한들의 평행이동(정보 보존).
**(c)** 비가역 `x = y + 5` (우변에 x 없음, 슬29~30): ① x 관련 옛 칸을 모두 ∞로(옛 제약 `x−y≤1` 폐기), ② 새 관계 `x − y = 5`를 두 부등식 `x−y≤5 ∧ y−x≤−5`로 설정, ③ x 무관 칸은 유지.
→ **`x−y≤5 ∧ y−x≤−5 ∧ z−w≤2`** (즉 `x−y=5 ∧ z−w≤2`). 옛 정밀 정보는 잃지만 새 관계는 정확 — 강의 16의 가역(치환·보존)/비가역(폐기·재설정) 구분과 동일한 구조가 DBM 칸 연산으로 구현된 것.

## 강의 18 — Abstract Interpretation 1 (Galois Connections)

### 문제 18-1 [증명·유도] (S, 슬라이드 21) ★
갈루아 연결의 두 조건 — **γ∘α 확장적(`x ⊑ γ(α(x))`)**과 **α∘γ 축소적(`α(γ(y)) ⊑ y`)** — 을 진술하고, 각각이 "건전성(안전)"과 "정밀성(최선)"에 대응함을 설명하라.

**풀이.**
- **확장적 `x ⊑ γ(α(x))`**: x를 추상화(α)했다 구체화(γ)로 되돌리면 원래보다 크거나 같다 → 추상화가 정보를 잃어도 **실제를 빠뜨리지 않음(과근사=안전=건전성)**.
- **축소적 `α(γ(y)) ⊑ y`**: y를 구체화했다 추상화하면 원래보다 작거나 같다 → α가 **가장 정밀한(타이트한) 추상값**을 줌(필요 이상 모호하게 하지 않음=정밀성).
즉 확장성은 "안전을 보장", 축소성은 "최선의 근사를 보장". 둘을 만족하는 단조 쌍 (α,γ)가 갈루아 연결이며, 분석의 건전성 기반이 된다.

---

### 문제 18-2 [계산·서술] (M, 슬라이드 24~25) ★
부호 도메인에서 γ∘α가 확장적임은 보이되 보통 항등함수가 **아니고**, α∘γ는 축소적이면서 보통 항등함수**임**을 각각 예로 보여라. 두 성질의 비대칭이 왜 생기는지 설명하라.

**풀이.**
- **γ∘α (확장, 항등 아님)**: `γ(α({1})) = γ(+) = {z>0} ⊋ {1}`. {1}이 모든 양수로 커짐 → 항등 아님(추상화가 정밀도를 잃음). 그래도 `{1} ⊆ {z>0}`이라 확장성 성립.
- **α∘γ (축소, 항등)**: `α(γ(+)) = α({z>0}) = +`. 펼쳤다 접으면 제자리 → 항등.
**비대칭 이유**: γ∘α는 "구체 정보를 추상으로 접으며 손실"이 생겨 커지지만(항등 아님), α∘γ는 부호 도메인의 각 추상값이 서로 다른 구체 집합을 의미해(중복 없음) 펼쳤다 접으면 정확히 돌아온다. (만약 추상값들이 같은 구체화를 가지면 α∘γ도 항등이 아닐 수 있음 — 슬26.)

### 문제 18-3 [개념·서술] (M, 슬라이드 32~34) ★★
변형 부호 격자 `Sign' = {⊥, 0⁻(≤0), 0⁺(≥0), ⊤}`는 갈루아 연결을 갖지 못한다. (a) 왜 `α({0})`을 유일하게 정할 수 없는지, (b) 그 결과 "더 정밀한 분석이 더 부정확한 결과"를 내는 역설이 어떻게 생기는지 설명하라.

**풀이.**
(a) 0은 0⁻(≤0)에도 0⁺(≥0)에도 속한다. α는 "x를 덮는 추상값들의 만남(⨅)"으로 정해야 하는데(슬27), 0⁻와 0⁺의 만남은 ⊥이고 ⊥는 {0}을 안 덮어 모순. 즉 **{0}을 가장 정밀하게 표현하는 유일한 원소가 없어** 갈루아 연결이 존재하지 않는다.
(b) 코드 `x = (e1 != e2)`에서 e1=e2가 항상 참이라 x는 항상 0. **덜 정밀한** 분석은 x를 0⁺로 추상화 → "x≥0" 증명 성공. **더 정밀한** 분석은 x=0임을 알고도 0을 0⁻로 추상화 → "x≥0" 증명 실패. 정밀도를 높였더니 결과가 나빠지는 **비단조적 역전**. 원인은 갈루아 연결이 없어 "0의 유일한 최선 추상값"이 없기 때문. 갈루아 연결이 있으면 이런 역설이 안 생긴다(sanity check).

### 문제 18-4 [설계·응용] (M, 슬라이드 35~38)
표현 함수(representation function) `β : V → L`로 도메인을 명세하면 α·γ·갈루아 연결이 자동으로 따라온다. (a) β로부터 α와 γ를 유도하는 공식을 쓰고, (b) 이 방식이 맵·곱 격자로 자동 확장됨을 설명하라.

**풀이.**
(a) `α(S) = ⨆_{v∈S} β(v)` (집합의 각 원소를 β로 보내 join); `γ(x) = {v | β(v) ⊑ x}` (x로 덮이는 원소들). 이 α,γ는 항상 갈루아 연결을 이룬다(β가 원소별이라 α가 완전 join 사상이 됨).
(b) **맵 격자**(슬37): 값 수준 갈루아 연결 (α,γ)가 있으면 `S→L1`과 `S→L2` 사이에 점별 갈루아 연결이 자동 성립(각 키에 α/γ 적용). **곱 격자**(슬38): 성분별로 자동 성립. 따라서 값 하나(β)만 잘 정하면, 상태(변수→값)·프로그램(노드별 곱) 전체로 갈루아 연결이 자동 확장된다. 설계자는 가장 작은 단위만 신경 쓰면 된다.

### 문제 18-5 [계산·서술] (M, 슬라이드 10~13) ★ 〔신규〕
다음 루프의 **수집 의미론**(구체 의미론)을 생각하자.
```
v1: entry
v2: x = 0
v3: if input()   (참이면 v4, 거짓이면 v5)
v4: x = x + 2    (다시 v3로)
v5: return
```
(a) 각 노드의 최소 고정점 `{|vi|}`를 구하라.
(b) `{|v3|}={|v4|}={|v5|}={[x↦z] | z∈ℤ}`도 제약식의 해(고정점)임을 확인하고, 왜 의미론은 **최소** 고정점으로 정의해야 하는지 답하라.
(c) lfp의 존재는 무엇이 보장하며, 그럼에도 일반적으로 계산 불가능한 이유는 무엇인가? 이것이 정적 분석의 존재 이유와 어떻게 연결되는가?

**풀이.**
**(a)** (슬11)
- `{|v1|} = {[x↦z] | z∈ℤ}` (진입: 임의 초기값).
- `{|v2|} = {[x↦0]}`.
- `{|v3|} = {[x↦z] | z∈{0,2,4,…}}` (루프 헤드: 0번 이상 +2 반복 — 비음수 짝수).
- `{|v4|} = {[x↦z] | z∈{2,4,6,…}}` (본문 통과 직후: 최소 한 번 +2).
- `{|v5|} = {[x↦z] | z∈{0,2,4,…}}`.
**(b)** "모든 정수"를 넣어도 제약식이 성립한다(전이가 ℤ를 ℤ로 보냄) — 고정점은 유일하지 않다. 그러나 그 해는 실제로 도달 불가능한 상태(x=1, x=−2 등)까지 포함해 **과도하게 크다**. "실제로 어떤 실행에서 나타날 수 있는 상태만" 담는 해는 가장 작은 해, 즉 **lfp**뿐이다. 더 큰 고정점은 안전하지만 부정확 — 의미론(기준)은 정확해야 하므로 lfp로 정의한다.
**(c)** cf가 단조이고 `𝒫(CState)ⁿ`이 완비 격자이므로 **Tarski 고정점 정리**가 lfp의 존재를 보장한다. 그러나 이 격자는 **무한 높이**라 Kleene 반복이 끝나지 않을 수 있고, 본질적으로 정지 문제와 얽혀 **lfp는 일반적으로 계산 불가능**하다. 바로 이것이 정적 분석의 존재 이유: 정확한 의미(구체 lfp)를 계산할 수 없으니, **유한 높이(또는 위드닝이 있는) 추상 도메인으로 과근사**해 계산 가능하게 만들고, 그 근사가 건전한지를 갈루아 연결로 따진다.

### 문제 18-6 [증명·유도] (M, 슬라이드 26~28) 〔신규〕
갈루아 연결 (α, γ)에 대해 다음을 증명·서술하라.
(a) 모든 x에 대해 `γ(α(γ(x))) = γ(x)`임을 확장성·축소성·단조성만으로 증명하라.
(b) 이로부터 "α∘γ가 항등이 아닌 것은 추상 격자에 **같은 구체화를 갖는 중복 원소**가 있다는 신호"임을 논하라.
(c) 갈루아 연결에서 γ가 α로(또 α가 γ로) **유일하게 결정**되는 공식을 쓰고, 그 실용적 의미를 답하라.

**풀이.**
**(a)** (⊒ 방향) γ∘α는 확장적이므로 x' = γ(x)에 적용하면 `γ(x) ⊑ γ(α(γ(x)))`.
(⊑ 방향) α∘γ는 축소적이므로 `α(γ(x)) ⊑ x`; γ가 단조이므로 양변에 γ를 적용해 `γ(α(γ(x))) ⊑ γ(x)`.
두 방향을 합쳐 **`γ(α(γ(x))) = γ(x)`**. ∎
**(b)** (a)에 의해, 설령 `α(γ(x)) = x' ≠ x`라도 `γ(x') = γ(x)` — 즉 x와 x'은 **의미(구체화)가 같다**. 따라서 α∘γ ≠ id가 되는 유일한 경우는 서로 다른 추상 원소가 같은 구체 집합을 의미할 때이고, 이는 추상 격자에 군더더기(중복) 원소가 있다는 신호다. 중복이 없는 도메인(부호 등)에선 α∘γ = id.
**(c)** `γ(y) = ⨆{x ∈ L₁ | α(x) ⊑ y}`, `α(x) = ⨅{y ∈ L₂ | x ⊑ γ(y)}` (슬27). 즉 α는 "x를 안전하게 덮는 추상값 중 가장 정밀한 것", γ는 "y 이하로 추상화되는 구체값을 전부 모은 것". **실용적 의미**: 분석 설계자는 α와 γ 중 **하나만** 명세하면 나머지가 수학적으로 결정된다 — 보통 더 직관적인 γ("이 추상값이 무엇을 의미하는가")를 정한다. 단, 임의의 α가 짝 γ를 갖는 것은 아니고 α가 **완전 join 사상**(γ는 완전 meet 사상)일 때 짝이 존재한다(슬29~30).

## 강의 19 — Abstract Interpretation 2 (Soundness Proof)

### 문제 19-1 [개념·서술] (M, 슬라이드 2·4·5) ★
건전성의 두 동치 정의 `{|P|} ⊑ γ([|P|])`(γ형)와 `α({|P|}) ⊑ [|P|]`(α형)를 쓰고, 둘이 동치인 이유(수반, adjunction)를 설명하라.

**풀이.**
- **γ형**: `{|P|} ⊑ γ([|P|])` — 분석 결과를 구체화한 것이 진짜 의미를 과근사(덮음).
- **α형**: `α({|P|}) ⊑ [|P|]` — 진짜 의미를 추상화한 것보다 분석 결과가 보수적.
**동치 이유**: 갈루아 연결은 **수반(adjunction)** `α(x) ⊑ y ⟺ x ⊑ γ(y)`와 동치(슬4). 여기에 x={|P|}, y=[|P|]를 대입하면 두 형태가 정확히 서로 변환된다. 증명·계산 시 편한 쪽(보통 추상 격자에서 비교하는 α형)을 선택해 쓸 수 있다.

### 문제 19-2 [증명·유도] (S, 슬라이드 7~8) ★
추상 연산 `+̂`가 구체 `+`의 건전한 추상일 조건을 쓰고, 부호 도메인에서 `− +̂ +`의 결과가 왜 `⊤`여야 하는지(0이나 다른 부호로 하면 왜 unsound인지) 보여라.

**풀이.**
건전 조건: `γa(x1) + γa(x2) ⊑ γa(x1 +̂ x2)` (펼쳐 더한 게 더해서 펼친 것에 포함).
`− +̂ +` 검증: `γa(−) + γa(+) = {z1+z2 | z1<0 ∧ z2>0} = ℤ`(음수+양수는 임의 정수 — 예: −1+1=0, −1+5=4, −5+1=−4). 이 ℤ를 덮으려면 `γa(− +̂ +) ⊇ ℤ`, 즉 `− +̂ + = ⊤`(γa(⊤)=ℤ)이어야 한다. 만약 `− +̂ + = +`로 하면 γa(+)={z>0}인데 ℤ⊄{z>0}(0이나 음수 누락) → unsound. 0이나 −로 해도 마찬가지. 따라서 ⊤만이 건전.

### 문제 19-3 [증명·유도] (M, 슬라이드 9~10) ★★
추상 식 평가 `eval`이 구체 `ceval`의 건전한 추상(`ceval(γb(σ),e) ⊑ γa(eval(σ,e))`)임을 **구조적 귀납법**으로 증명하라. 합성 사례 `e = e1 + e2`의 부등식 사슬을 명확히 쓰라.

**풀이.**
구조적 귀납. 기저(변수·상수·input)는 직접 확인(슬9). 합성 `e1+e2`:
귀납 가설(IH): `ceval(γb(σ),ei) ⊑ γa(eval(σ,ei))` (i=1,2).
```
ceval(γb(σ), e1+e2)
 ⊑ ceval(γb(σ),e1) + ceval(γb(σ),e2)        (구체 덧셈 분해)
 ⊑ γa(eval(σ,e1)) + γa(eval(σ,e2))          (IH)
 ⊑ γa(eval(σ,e1) +̂ eval(σ,e2))              (+̂의 건전성, 문제 19-2)
 = γa(eval(σ, e1+e2))                         (eval 정의)
```
각 단계가 이미 증명한 더 작은 조각(IH, +̂)에 의존 — 부품의 건전성이 조립품으로 합성됨.

### 문제 19-4 [증명·유도] (S, 슬라이드 21~22) ★★★
**건전성 정리**를 진술하라: 한 스텝 건전성 `cf∘γ ⊑ γ∘f`이면 고정점 건전성 `lfp(cf) ⊑ γ(lfp(f))`. 그리고 Tarski 정리를 이용한 3줄 증명을 제시하라.

**풀이.**
**정리**: 완비 격자 L1,L2와 단조 γ,cf,f에 대해 `cf∘γ ⊑ γ∘f`이면 `lfp(cf) ⊑ γ(lfp(f))`.
**증명**:
1. `cf(γ(lfp(f))) ⊑ γ(f(lfp(f)))` (한 스텝 건전성 적용) `= γ(lfp(f))` (lfp(f)는 f의 고정점이라 f(lfp(f))=lfp(f)).
2. 따라서 `cf(γ(lfp(f))) ⊑ γ(lfp(f))` — 즉 `γ(lfp(f))`는 cf의 **후고정점**(`cf(x)⊑x`인 점).
3. Tarski 정리에 의해 `lfp(cf) = ⨅{x | cf(x)⊑x}`는 모든 후고정점 이하 → `lfp(cf) ⊑ γ(lfp(f))`. ∎
의미: 한 스텝의 건전성만 증명하면 전체 분석(고정점)의 건전성이 자동으로 따라온다.

### 문제 19-5 [증명·유도] (S, 슬라이드 24)
위드닝을 사용한 분석이 여전히 건전함을 증명하라(`lfp(f) ⊑ [|P|]`를 가정).

**풀이.**
위드닝 결과 `[|P|]`는 종료를 위해 고정점보다 위로 보낸 것이라 `lfp(f) ⊑ [|P|]`. γ가 단조이므로:
`{|P|} = lfp(cf) ⊑ γ(lfp(f)) ⊑ γ([|P|])`.
(첫 ⊑는 건전성 정리(문제 19-4), 둘째 ⊑는 γ 단조 + `lfp(f)⊑[|P|]`.) 따라서 `{|P|} ⊑ γ([|P|])` — 건전성 유지. 위드닝은 더 보수적이 되어(정밀도 손실) 종료를 사되 건전성은 절대 깨지 않는다.

### 문제 19-6 [증명·유도] (M, 슬라이드 11~14) 〔신규〕
부호 분석의 건전성 증명에서 식 평가 외의 세 조각의 건전성을 각각 진술·증명하라.
(a) 후속 노드: `succ`가 `csucc`의 건전한 추상일 조건과 if 노드에서의 성립 이유.
(b) 합류: `JOIN`이 `CJOIN`의 건전한 추상일 조건과 증명에 쓰이는 두 재료.
(c) 진입 노드: 분석이 진입을 `⊤`로 두는 것이 왜 건전한가.

**풀이.**
**(a)** 조건: `csucc(R, v) ⊆ succ(v)` — 구체 실행이 실제로 갈 수 있는 후속이 분석이 보는 후속에 포함. if 노드에서 구체는 상태에 따라 참 또는 거짓 가지 **한쪽**으로 가지만(T∪F), 분석은 **양쪽 모두** `{true(v), false(v)}`를 후속으로 둔다 → 포함 성립. 그 외 노드는 둘이 같다. **제어 흐름도 과근사**(가능한 분기를 다 봄)라야 건전하다.
**(b)** 조건: `CJOIN(v)(γb(σ₁),…,γb(σₙ)) ⊑ γb(JOIN(v)(σ₁,…,σₙ))` — "펼쳐서 구체 합류"가 "추상 합류 후 펼치기"에 덮임. 증명 재료는 ① succ의 건전성(슬11): 구체가 합류로 보내는 선행자들이 분석의 선행자에 포함, ② γb의 단조성: 각 선행자 w에 대해 `σw ⊑ ⨆σw`이므로 `γb(σw) ⊑ γb(⨆σw)`. 두 재료를 결합하면 구체 합류의 모든 상태가 추상 join의 구체화 안에 들어간다.
**(c)** 구체 의미론의 진입은 "모든 가능한 초기 상태"(임의 정수 대입). 분석의 진입은 ⊤(모든 변수 부호 미정)이고 `γ(⊤) = 모든 상태`이므로 자명하게 덮는다 → 건전. (만약 진입을 ⊤보다 작게 두면 일부 초기 상태를 누락해 unsound.)
이 세 조각 + eval(문제 19-3)이 합쳐져 각 노드 전이 `fv`의 건전성(슬13), 나아가 전체 `f`의 건전성 `cf∘γc ⊑ γc∘f`(슬15)가 된다 — 조각별 건전성의 총조립.

### 문제 19-7 [설계·응용] (F, 슬라이드 23) ★ 〔신규〕
**건전성 증명의 5단계 레시피**(슬23)를 진술하고, 새 분석인 **홀짝(parity) 분석**(추상값 {⊥, 짝, 홀, ⊤})에 각 단계를 어떻게 적용할지 개요를 설계하라.

**풀이.**
**레시피**: ① 분석 명세(분석 격자 + 단조 제약 규칙) ② 수집 의미론 명세(의미 격자 + 단조 제약 규칙) ③ 연결 확립(α가 완전 join 사상 또는 γ가 완전 meet 사상 → 갈루아 연결 보장) ④ 분석 제약의 **각 조각**이 대응 의미 조각의 건전한 추상임을 증명 ⑤ 건전성 정리로 전체 건전성 도출.
**홀짝 분석 적용**:
① 격자 `Parity = {⊥ ⊑ 짝,홀 ⊑ ⊤}`, 상태 `Var→Parity`(맵 격자), 전이: 대입 `x=e`는 `σ[x↦eval(σ,e)]`, `+̂` 표: 짝+̂짝=짝, 짝+̂홀=홀, 홀+̂홀=짝, ⊤ 관련은 ⊤ — 모두 단조.
② 수집 의미론은 강의 18 그대로(`𝒫(CState)`, cf, lfp) — 재사용.
③ 표현 함수 `β(z) = 짝 (z가 짝수), 홀 (홀수)`로부터 `α(S)=⨆_{z∈S}β(z)`, `γ(짝)={짝수}, γ(홀)={홀수}, γ(⊤)=ℤ, γ(⊥)=∅` 자동 유도(강의 18 슬35~36) → α는 완전 join 사상이므로 갈루아 연결 성립; 맵·곱 격자로 자동 확장(슬37~38).
④ 조각 증명: `γ(짝)+γ(짝)={짝+짝}⊆{짝수}=γ(짝)` 등 `+̂` 표의 각 칸 검증; eval은 구조적 귀납(문제 19-3과 동일 틀); succ·JOIN·진입은 문제 19-6과 동일(도메인 무관 논증).
⑤ 각 노드 전이의 건전성 → `cf∘γ ⊑ γ∘f` → 건전성 정리로 `lfp(cf) ⊑ γ(lfp(f))`. Parity는 유한 높이라 위드닝 불요, 그래도 필요하면 슬24 논증 추가.
**교훈**: 도메인 고유 작업은 사실상 ③의 β와 ④의 연산 표 검증뿐 — 나머지는 표준 기계.

## 강의 20 — Abstract Interpretation 3 (Trace Semantics)

### 문제 20-1 [개념·서술] (M, 슬라이드 2~3) ★
도달 상태 수집 의미론이 **부족한** 분석의 예를 들고, 어떤 정보를 못 담아 부족한지 설명하라.

**풀이.**
수집 의미론은 "각 지점에서 가능한 상태 집합"만 담아, **"어떻게 그 상태에 도달했나"**(실행 경로·역사, 어떤 식이 평가됐나, 지점 간 상태 관계)는 버린다. 예: `y=0; if input() {x=1} else {x=y+1}`의 끝 상태는 두 분기 모두 `[x:1,y:0]`이라 수집 의미론은 then/else를 구분 못 하고, "`y+1`이 평가됐나"도 모른다. **사용 가능 식 분석**("이 식이 이미 계산됐나")이나 **도달 정의 분석**("어느 대입이 살아 왔나")은 이 실행 역사가 필요해 수집 의미론으로는 건전성을 증명할 수 없다 → 트레이스 의미론이 필요.

### 문제 20-2 [개념·서술] (M, 슬라이드 4·7·8)
**트레이스 의미론**을 정의하고, `《P》`가 어떻게 최소 고정점으로 정의되는지 쓰라.

**풀이.**
**트레이스** = (프로그램 지점, 상태) 쌍의 유한 수열 `Trace = (Node × CState)*`. 실행을 한 걸음씩 기록해 *역사 전체*를 담는다. 트레이스 의미론 `《P》 ∈ 𝒫(Trace)`는 "진입에서 시작해 CFG를 따라 한 걸음씩 진행하는 모든 유한 트레이스"이며, `tf(T) = I ∪ grow(T)`의 **최소 고정점** `《P》 = lfp(tf)`로 정의된다. 여기서 `I`는 초기 트레이스(진입·임의 초기 상태), `grow(T) = {π·s·s' | π·s∈T ∧ s→s'}`는 각 트레이스를 한 걸음 늘린 것. (강의 18의 수집 의미론 lfp 구조와 동일, 도메인만 트레이스.)

### 문제 20-3 [증명·서술] (M, 슬라이드 10~12) ★★

**풀이.**

**합성성의 중요성**: 갈루아 연결은 합성된다(슬11) — 트레이스→수집 (αt)와 수집→분석 도메인 (αc)을 합치면 **트레이스→분석 도메인** 갈루아 연결이 한 번에 생긴다. 따라서 여러 추상화 층을 따로 다루지 않고, 가장 구체적인 의미론(트레이스)에서 분석 결과까지 **하나의 사슬**로 잇고, 건전성도 합성해 증명할 수 있다(슬15).

### 문제 20-4 [설계·증명] (F, 슬라이드 16~19) ★★

**풀이.**

"vj 이후 x 재정의 여부"는 **실행 경로(트레이스)를 봐야** 알 수 있으므로, 끝 상태만 담는 수집 의미론으로는 αRD를 정의할 수조차 없다. 트레이스 의미론이 있어야 비로소 "살아남은 정의"를 추출하고 kill/gen 전이의 건전성(슬18~19: vj=vi면 gen, 아니면 재정의 없어 kill 안 됨)을 증명할 수 있다.

### 문제 20-5 [계산·추적] (M, 슬라이드 5~9) 〔신규〕
다음 프로그램의 트레이스 의미론 `《P》`를 길이별로 나열하라(상태는 x,y만, 초기값은 임의 정수 z₁,z₂).
```
v0: entry
v1: y = 0
v2: if input()
v3: x = 1        (then)
v4: x = y + 1    (else)
v5: return
```
또 (a) then/else 두 경로의 **끝 상태**가 같음에도 트레이스 의미론이 둘을 구분하는 이유, (b) `αt`로 상태만 추출하면 어느 정보가 사라지는지 답하라.

**풀이.**
한 걸음 전이 `(v,ρ) → (v',ρ')`는 `v'∈csucc(ρ,v)`, `ρ'∈ct_{v'}(ρ)`로 정의(슬5~6). 길이별 트레이스:
- 길이 1 (I): `(v0, [x↦z₁, y↦z₂])` — 모든 z₁,z₂.
- 길이 2: `(v0,[x↦z₁,y↦z₂])·(v1,[x↦z₁,y↦0])` (y=0 수행).
- 길이 3: `…·(v2,[x↦z₁,y↦0])` (분기 노드는 상태 불변).
- 길이 4 (두 갈래): then `…·(v3,[x↦1,y↦0])`, else `…·(v4,[x↦1,y↦0])` (y+1=0+1=1).
- 길이 5: then `…·(v3,…)·(v5,[x↦1,y↦0])`, else `…·(v4,…)·(v5,[x↦1,y↦0])`.
《P》는 이 모든 **접두(부분 실행) 트레이스의 집합**(끝까지 안 간 것도 포함).
**(a)** 길이 4 이후 두 경로의 마지막 상태는 똑같이 `[x↦1,y↦0]`이지만, 트레이스는 **v3을 거쳤는지 v4를 거쳤는지가 수열 안에 기록**되어 별개의 원소다. "어느 경로로 왔나", "식 `y+1`이 평가됐나"가 구분된다.
**(b)** `αt`는 각 지점으로 끝나는 트레이스의 **마지막 상태만** 추출하므로, v5에선 두 트레이스가 같은 상태 `[x↦1,y↦0]` 하나로 합쳐진다 — **역사(경로·평가된 식·정의의 생존 여부)가 사라진다**. 이것이 수집 의미론이 도달 정의·사용 가능 식 분석을 정당화하지 못하는 이유(문제 20-1·20-4).

### 문제 20-6 [증명·유도] (M, 슬라이드 13~15) ★★ 〔신규〕
(a) 수집 의미론이 트레이스 의미론의 건전한 추상임을 보이는 부등식 `αt(tf(T)) ⊑ cf(αt(T))`를 **경우 나누기**로 증명하라.
(b) 이 부등식과 강의 19의 `cf∘γc ⊑ γc∘f`를 **합성**해 `lfp(tf) ⊑ (γt∘γc)(lfp(f))`를 유도하라.

**풀이.**
**(a)** `αt(T)=(R₁,…,Rₙ)`이라 하고, `ρ ∈ αt(tf(T))ᵢ`를 임의로 잡으면 어떤 π에 대해 `π·(vᵢ,ρ) ∈ tf(T) = I ∪ grow(T)`.
- **경우 1: `π·(vᵢ,ρ) ∈ I`** (길이 1 초기 트레이스). 그러면 vᵢ = entry이고 ρ는 임의 초기 상태 → cf의 진입 규칙("모든 초기 상태")에 의해 `ρ ∈ cfᵢ(R₁,…,Rₙ)`.
- **경우 2: `π·(vᵢ,ρ) ∈ grow(T)`**. 정의상 `π = π'·(vⱼ,ρ')`로 쓸 수 있고 `π ∈ T`, `(vⱼ,ρ') → (vᵢ,ρ)`. π∈T이므로 αt 정의에 의해 `ρ' ∈ Rⱼ`. 전이 정의에 의해 `vᵢ ∈ csucc(ρ',vⱼ)`이고 `ρ ∈ ct_{vᵢ}(ρ')`. 이는 정확히 수집 의미론 전이 cfᵢ가 Rⱼ로부터 만들어 내는 상태의 조건이므로 `ρ ∈ cfᵢ(R₁,…,Rₙ)`.
두 경우 모두 포함 → `αt(tf(T)) ⊑ cf(αt(T))` (수반으로 γ형 `tf∘γt ⊑ γt∘cf`와 동치). ∎
**(b)** 부등식 사슬(슬15):
```
tf ∘ (γt∘γc) = (tf∘γt) ∘ γc
            ⊑ (γt∘cf) ∘ γc        ((a)의 γ형)
            = γt ∘ (cf∘γc)
            ⊑ γt ∘ (γc∘f)          (강의 19의 한 스텝 건전성)
            = (γt∘γc) ∘ f
```
즉 합성 구체화 `γt∘γc`에 대한 **한 스텝 건전성**이 성립. 갈루아 연결도 합성되므로(슬11~12) (α,γ) 쌍이 유효하고, **건전성 정리(강의 19 슬22, Tarski + 후고정점)**를 적용하면:
`lfp(tf) ⊑ (γt∘γc)(lfp(f))`. ∎
의미: 분석은 수집 의미론뿐 아니라 **가장 구체적인 트레이스 의미론에 대해서도** 건전 — 층층이 쌓은 추상화의 건전성이 합성으로 한 번에 얻어진다.

### 문제 X-2 [증명·유도] (강의 7~8 ↔ 12) ★★
강의 12의 **live guard 분석**과 **available guard 분석**이 각각 강의 7~8의 어떤 고전 데이터플로우 분석에 대응하는지 밝히고, (방향, may/must, JOIN 연산)의 세 속성이 어떻게 일치하는지 표로 보여라. 또 available 분석의 진입값이 왜 live 분석의 결과인지 논하라.

**풀이.**
| | 고전 분석 (강7~8) | guard 분석 (강12) | 방향 | may/must | JOIN |
|---|---|---|---|---|---|
| live guard | Live Variable | 진입 시 잡힌 락 | backward | may | ∪ (후속자) |
| available guard | Available Expression | 반환 시 잡힌 락 | forward | must | ∩ (선행자) |
대응이 정확하다: live guard는 "미래에 풀릴(=지금 잡힌) 락"을 후방으로 추적(살아있는 변수와 동형), available guard는 "이미 잡혀 available한 락"을 전방·교집합으로 추적(사용가능 식과 동형).
**진입값 연결**: available(전방)은 함수 진입 상태가 필요한데, 그것은 "진입 시 잡혀 있는 락" = **live 분석의 결과**다. 그래서 먼저 live(후방)로 진입 락을 구하고, 그 값을 available(전방)의 진입 상태로 넣는다(강12 슬14의 "먼저 live, 그다음 available" 순서의 이유).

### 문제 X-3 [개념·서술] (강의 14 ↔ 15) ★★
강의 14(흐름 무감각 Andersen/Steensgaard)와 강의 15(흐름 감각)의 포인터 분석을 **정밀도·비용·핵심 난제**의 관점에서 비교하라. 특히 흐름 감각이 추가로 얻는 정밀도의 원천과, 그 대가로 새로 생기는 건전성 난제(strong/weak update)를 연결해 설명하라.

**풀이.**

### 문제 X-5 [개념·서술] (강의 16 ↔ 17) ★★
배열 경계 검사(인덱스 `z < x`, 즉 `z − x ≤ −1`)와 바이너리 분석(`x = sp − 4`)이라는 두 응용에 대해, **구간·팔각형·다면체** 중 각각 어느 도메인이 **최소한으로 충분**한지 답하고 이유를 설명하라.

**풀이.**
- 두 응용의 핵심 제약은 모두 **변수 두 개의 차이** 형태다: `z − x ≤ −1`, `x − sp ≤ −4 ∧ sp − x ≤ 4`(즉 x=sp−4). 이는 `±x±y≤c` 꼴이므로 **팔각형으로 충분**하다.
- **구간으론 불충분**: 변수 간 관계(차이)를 표현 못 해 `z<x`나 `x=sp−4`를 못 잡는다.
- **다면체는 과함**: 임의 계수 부등식이 필요 없는데도(차이만 필요) 다면체는 비싸다(무제한 부등식, 지수적 비용 가능).

### 문제 X-11 [증명·유도] (강의 15 ↔ 19) ★★★ 〔신규〕
강의 15의 **strong/weak update 규칙**을 강의 19의 건전성 언어로 다시 진술하라.
(a) 간접 대입 `*z = e` 노드의 **구체 전이** cfv와 **추상 전이** fv를 쓰고, 건전성 조건 `cfv(γ(σ)) ⊑ γ(fv(σ))`가 무엇을 요구하는지 밝혀라.
(b) z가 {x,y}를 가리키는 상태(강15 슬10)에서 **무조건 strong update**가 이 조건을 위반함을 구체 상태를 들어 보여라.
(c) weak update가 항상 조건을 만족하는 이유를 답하라.

**풀이.**
**(a)** 구체 전이: `cfv(R) = {ρ[c↦z] | ρ∈R ∧ c ∈ (ρ에서 z가 가리키는 실제 셀) ∧ z∈ceval(ρ,e)}` — 각 구체 실행에서 **단 하나의 실제 셀**만 바뀐다. 추상 전이: `fv(σ) = update(σ, eval(σ,z), eval(σ,e))`. 건전성 조건은 "γ(σ)의 어떤 상태가 실제로 한 셀을 바꾼 결과가, 추상 update 후의 γ 안에 **반드시 들어 있어야** 함"을 요구한다 — 강의 19 슬16의 가환 사각형(`cf∘γ ⊑ γ∘f`)의 이 노드 버전이다.
**(b)** σ = `[x↦[1,1], y↦[2,2], z↦(⊥,{x,y})]`, e=3. 구체 상태 ρ = `[x↦1, y↦2, z↦&y]` ∈ γ(σ). 구체 전이는 **y만** 바꿔 ρ' = `[x↦1, y↦3]`. 그런데 무조건 strong update는 σ' = `[x↦[3,3], y↦[3,3]]`을 내고, γ(σ')의 모든 상태는 x=3이므로 **ρ'(x=1) ∉ γ(σ')** → `cfv(γ(σ)) ⋢ γ(fv(σ))` — 한 스텝 건전성 위반. (이 한 노드의 위반이 건전성 정리의 전제를 깨, 고정점 결과 전체가 `{|P|} ⊑ γ([|P|])`를 잃는다.)
**(c)** weak update는 각 후보 셀 c에 `σ(c) ⊔ v`를 준다. 구체 실행이 c를 바꿨다면 새 값은 `γ(v)` 쪽에, 바꾸지 않았다면 옛 값은 `γ(σ(c))` 쪽에 들어 있고, ⊔의 구체화는 양쪽을 모두 포함(`γ(a)∪γ(b) ⊆ γ(a⊔b)`)하므로 어느 경우든 결과 상태가 γ(fv(σ)) 안에 있다 → 항상 건전. strong update는 `γ(v)`만 남기므로 "그 추상 셀의 **모든** 런타임 셀이 실제로 바뀜"이 보장될 때(단일 런타임 셀)만 건전 — 강의 15의 규칙(비재귀 지역 변수)이 정확히 이 보장 조건이다.

### 문제 X-12 [계산·추적/개념] (강의 9 ↔ 16 ↔ 17) ★★ 〔신규〕
두 구체 상태(점) `(x,y) = (0,0)`과 `(1,2)`의 join을 네 도메인 — **구간(강9), 선형 등식(강16), 팔각형(강17), 다면체(강16)** — 에서 각각 계산하고, 결과의 정밀도와 비용을 비교하라.

**풀이.**
- **구간** (변수별 독립): x∈[0,1], y∈[0,2] → **직사각형 박스**. 관계 정보 전무. 비용 O(n).
- **선형 등식** (아핀 껍질): 점 P=(0,0), 방향 P'−P=(1,2) → 두 점을 지나는 직선 **`y = 2x`** (정확히 `2x − y = 0`). 두 점 사이·바깥의 직선 전체를 포함하지만 **관계는 정확히 포착**. 비용 다항(가우스 소거).
- **팔각형** (칸별 max): 각 점의 팔각형 제약을 칸별로 합치면 `0≤x≤1 ∧ 0≤y≤2 ∧ 0≤x+y≤3 ∧ −1≤x−y≤0` → 박스를 대각선으로 깎은 영역. `y=2x`는 **계수 2라 표현 불가** — 예컨대 (1,1)이 포함되는 과근사. 비용 O(n²) 메모리, 정규화 O(n³).
- **다면체** (볼록 껍질): 두 점의 볼록 껍질 = **선분** `y=2x ∧ 0≤x≤1`. 네 도메인 중 가장 작은(정밀한) 결과. 비용은 최악 지수적.
**비교**: 정밀도는 `다면체(선분) ⊊ 등식∩구간 ⊊ 팔각형 ⊊ 구간` 순으로 손실이 커진다. 흥미로운 점: **등식 도메인은 팔각형이 못 잡는 `y=2x`(임의 계수 관계)를 잡지만**, 유계 정보(0≤x≤1)는 전혀 못 잡는다 — 두 도메인의 표현력은 포함 관계가 아니라 **서로 다른 축**이다(팔각형 ⊉ 등식, 등식 ⊉ 팔각형; 둘 다 다면체에 포함). 도메인 선택은 "어떤 형태의 사실이 필요한가"(강17 슬5~7, X-5)에 달려 있다.

### 문제 X-13 [증명·유도] (강의 18 ↔ 19 ↔ 20) ★★★ 〔신규〕
구간 도메인 분석이 위드닝으로 종료해 결과 `[|P|]`를 냈다. 이 결과가 **트레이스 의미론에 대해서도 건전**함, 즉 `《P》 = lfp(tf) ⊑ (γt∘γc)([|P|])`임을, 강의 18·19·20의 정리들을 사슬로 엮어 증명하라(각 단계에 사용한 정리를 명시할 것).

**풀이.**
재료를 나열하고 사슬로 잇는다.
1. **갈루아 연결 합성**(강20 슬11~12): (αt,γt) 트레이스↔수집, (αc,γc) 수집↔구간이 각각 갈루아 연결이므로 합성 `(αc∘αt, γt∘γc)`도 트레이스↔구간 갈루아 연결.
2. **한 스텝 건전성의 합성**(강20 슬13~15): `tf∘γt ⊑ γt∘cf`(수집이 트레이스의 건전한 추상; 문제 20-6(a))와 `cf∘γc ⊑ γc∘f`(구간 분석의 한 스텝 건전성; 강19의 조각별 증명 — eval·succ·JOIN·전이의 합성)에서
`tf∘(γt∘γc) ⊑ γt∘(cf∘γc) ⊑ (γt∘γc)∘f`.
3. **건전성 정리**(강19 슬22, Tarski): 2의 한 스텝 건전성으로부터 `lfp(tf) ⊑ (γt∘γc)(lfp(f))`. (γ(lfp(f))가 tf의 후고정점 → lfp는 모든 후고정점 이하.)
4. **위드닝 건전성**(강19 슬24): 위드닝 결과는 `lfp(f) ⊑ [|P|]`. γt∘γc가 단조(단조 함수의 합성)이므로 `(γt∘γc)(lfp(f)) ⊑ (γt∘γc)([|P|])`.
5. 3과 4를 이으면: `《P》 = lfp(tf) ⊑ (γt∘γc)(lfp(f)) ⊑ (γt∘γc)([|P|])`. ∎
**의미**: "갈루아 연결(18) → 조각별·한 스텝 건전성(19) → 정리로 고정점 건전성(19) → 위드닝도 무사(19) → 의미론 층을 트레이스까지 내려도 합성으로 무사(20)" — 세 강의의 결과가 하나의 부등식 사슬로 완결되는, 추상 해석 이론의 전체 그림이다.

### 문제 X-14 [개념·서술] (강의 12 ↔ 13, 강의 8 언급) ★★ 〔신규〕
강의 13의 읽기/쓰기 집합 분석에서 **R은 합집합(∪), W는 교집합(∩)**으로 합류한다. 이 비대칭을 강의 12의 live/available guard 분석, 나아가 강의 7~8의 데이터플로우 4분면(방향 × may/must)과 연결해 일반 원리로 정리하라.

**풀이.**
**대응표**:
| 정보 | 방향 | may/must | 합류 | "위험"의 방향 |
|---|---|---|---|---|
| live guard (강12) | backward | may | ∪ | 진입 요구 락 **누락**하면 보호 없는 접근 |
| available guard (강12) | forward | must | ∩ | 잡힘을 **과장**하면 없는 가드를 반환 |
| 읽기 집합 R (강13) | forward | may | ∪ | 입력 가능성 **누락**하면 필요한 인자를 제거 |
| 쓰기 집합 W (강13) | forward | must | ∩ | 출력을 **과장**하면 안 쓴 경로에서 미정의 값 반환 |
**일반 원리**: 어떤 사실을 분석 결과로 "주장"했을 때 —
- 주장의 **누락**이 위험한(한 경로의 가능성만으로 대응해야 하는) 정보는 **may·∪**: 모든 경로의 가능성을 빠짐없이 모은다.
- 주장의 **과장**이 위험한(모든 경로에서 성립해야 행동할 수 있는) 정보는 **must·∩**: 모든 경로의 공통만 남긴다.
이는 강의 7~8의 4분면(forward/backward × may/must)이 도메인을 바꿔(변수→락→메모리 접근) 반복 출현하는 것이다. 한 분석 안에 may 성분(R)과 must 성분(W)이 **공존**할 수 있다는 점(강13의 상태 (R,W))이 4분면 표의 한 칸이 아니라 "성분별 선택"임을 보여 준다 — 격자를 곱(R격자 ⊆ × W격자 ⊇)으로 설계하면 합류는 성분별 join으로 자동 유도된다(강의 5~6).
